# Новостной Агрегатор (Nuxt 4 + SSR)

Приложение для агрегации, поиска и пагинации новостных лент в реальном времени из источников Mos.ru и Lenta.ru. Проект разработан на базе **Nuxt 4** с использованием универсального рендеринга, централизованного управления состоянием через **Pinia** и строгого разделения обязанностей (Single Responsibility Principle).

## 🛠️ Технологический стек

*   **Framework:** Nuxt 4 (Universal Rendering Mode)
*   **State Management:** Pinia Store
*   **Frontend UI:** Vue 3 (Script Setup, TypeScript), Tailwind CSS
*   **Server/Backend:** Nitro Engine
*   **XML Processing:** fast-xml-parser

## 🏗️ Архитектура и структура проекта

Проект разделен на изолированные слои с четким разграничением зон ответственности (Separation of Concerns) и соблюдением принципа Single Responsibility:

```text
├── components/          # Компоненты интерфейса (Atomic Design)
│   ├── Atoms/
│   │   └── AppIcon.vue          # Атом: универсальная обёртка для SVG-иконок
│   ├── Molecules/
│   │   ├── FilterTabs.vue        # Молекула: табы фильтрации источников новостей
│   │   ├── Pagination.vue        # Молекула: пагинатор (обертка над UPagination)
│   │   ├── SearchInput.vue       # Молекула: универсальный переиспользуемый инпут
│   │   ├── Toolbar.vue           # Молекула: тулбар (агрегирует фильтры и переключатель сетки)
│   │   └── ViewSwitcher.vue      # Молекула: кнопки переключения сетки (grid/list)
│   └── Organisms/
│       ├── Header.vue            # Организм: шапка (заголовок, поиск и сброс фильтров)
│       ├── NewsFeed.vue          # Организм: главный фид (координация списков, заглушек и пагинации)
│       ├── NewsList.vue          # Организм: сетка новостей (управление отображением карточек)
│       └── NewsCard.vue          # Организм: монолитная кликабельная карточка новости
├── pages/
│   └── news/
│       └── [id].vue     # Динамический роут страниц новостей: оркестрация useAsyncData и наполнение стора
├── server/              # Серверная логика (Nitro Engine)
│   ├── api/
│   │   └── news.ts      # Транспортный уровень: обработка query-параметров, фильтрация, пагинация
│   └── utils/
│       ├── constants.ts # Конфигурация источников (RSS-потоков) и регулярные выражения
│       ├── date.ts      # Утилита форматирования даты в формат DD.MM.YYYY
│       └── parsers.ts   # Изолированная логика разбора XML/CDATA структур для каждого провайдера
├── stores/
│   └── useNewsStore.ts  # Глобальное централизованное состояние для кэширования новостей
```

### Декомпозиция UI-слоя по методологии Atomic Design:

*   **Атомы (`Atoms/`):** Минимальные, неделимые элементы интерфейса. Компонент `AppIcon` инкапсулирует в себе базовую логику рендеринга динамических SVG-компонентов, управление их размером (`fontControlled`) и заливкой цветности (`filled`).
*   **Молекулы (`Molecules/`):** Простые комбинации атомов и нативных тегов. Компоненты `SearchInput` или `FilterTabs` являются чистыми — они принимают и отдают данные через свойства и события (`defineModel`, `emit`), не завязываясь на роутер или глобальный стейт, что делает их полностью переиспользуемыми.
*   **Организмы (`Organisms/`):** Сложные функциональные блоки, управляющие бизнес-логикой отображения. Например, организм `NewsFeed` оркестрирует показ списков новостей, пагинации или вызов заглушки «Ничего не найдено».
*   **Страницы (`pages/`):** Верхнеуровневые контейнеры. Файл `[id].vue` выполняет роль диспетчера данных: реактивно запрашивает информацию через `useAsyncData` на основе URL, атомарно сохраняет результаты в Pinia-стор и распределяет их вниз по иерархии компонентов.

### Ключевые особенности реализации:

*   **Универсальный рендеринг (SSR):** Сбор данных с внешних серверов, парсинг и фильтрация происходят на стороне сервера. Клиент получает полностью готовый HTML, что исключает сдвиги интерфейса (Layout Shift).
*   **Управление состоянием (Pinia + State-in-URL):** Для централизованного управления данными используется **Pinia Store** (`useNewsStore`). Чтобы сохранить полноценный SSR и работоспособность истории браузера, реализован гибридный подход: пагинация и поисковые фильтры синхронизируются через `VueRouter` в URL, а результаты серверного парсинга кэшируются в глобальном сторе на этапе выполнения `useAsyncData`. Это гарантирует уникальный постоянный адрес для каждого состояния и позволяет делиться ссылками.
*   **Параллельная обработка и отказоустойчивость:** Запросы к сторонним ресурсам выполняются асинхронно через `Promise.allSettled`. Сбой или задержка одного из внешних источников не блокирует работу приложения и отдачу новостей из других фидов.
*   **Синхронизация состояния без Web API:** Выбор типа сетки (`grid` / `list`) сохраняется в `useCookie`, а поисковые запросы и пагинация синхронизируются через `VueRouter`. В хуках жизненного цикла не используются нативные объекты браузера (`window`, `localStorage`), что обеспечивает безопасность SSR-сборки.
*   **Обработка ошибок на клиенте:** Перехват сетевых и серверных сбоев реализован через деструктуризацию объекта `error` из `useAsyncData`. Интерфейс предоставляет пользователю возможность повторить запрос без перезагрузки страницы с помощью метода `refresh()`.

## 📦 Установка и запуск

1. Установка зависимостей:
```bash
pnpm install
```

2. Запуск в режиме разработки (`http://localhost:3000`):
```bash
pnpm run dev
```

3. Сборка продакшен-версии:
```bash
pnpm run build
```
